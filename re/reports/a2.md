## Review fixes
I checked each reviewer finding against the binary before acting. No finding was rejected.

1. **User-Agent token is `Alamofire/5.8.0` in the binary but `5.12.2` in the rebuild (app/project.yml).** Confirmed, not applied: the file is not a2's, so it goes to main.
   The `HTTPHeader.defaultUserAgent` closure at 0x1001428b4–0x1001428d0 appends the small string x0=0x7269666f6d616c41, x1=0xef302e382e352f65, which decodes to "Alamofire/5.8.0" (count 15). nm.txt has no `AFInfo` symbol. project.yml says `from: "5.9.0"`, so matching the binary needs `exactVersion: 5.8.0`, not a bump. The `Alamofire/5.10.2` example in RECONSTRUCTION.md:66 is also wrong. Impact is low: the mirror accepts any non-curl UA when `X-Hdrezka-Ios-App` is present.
2. **The request tests take a snapshot of live AppStorage.** Confirmed and fixed.
   At 0x1000ecb5c (closure #1 in closure #3 in HomeView.body) the binary awaits `HeaderUpdater.updateHeader()` when scenePhase == .active and writes an AppStorage (0x1000eccac). The test bundle is hosted by the app (`TEST_HOST`), so once the view agents restore that call, `remoteVersion` can change during a test (on a fresh simulator, "" becomes "2.2.5").
   The three spies now override `settingStore`/`remoteVersion` with fixed values ("mirror.test", "9.9.9-test"). These match no default ("", "0.0.0", "ijobs.app"), so the assertions also prove that the URL and the version header are read from those properties. Production code is unchanged.
3. **Answer handling has no tests.** Confirmed. The logic already matched the binary; I added tests.
   What I re-checked:
   - login (0x10003a3b4): `as! [String: Any]` (cast flags 0x7), then `["success"]!` (brk on nil), then `as! Bool`.
   - createBookmarksCategory (0x10003c200): `as! [String: Any]`, then `["id"] as? Int` (flags 0x6), then `Bookmark(id:name:)` or nil.
   - PeopleRepository (0x1000f65d4): builds `PeopleNetwork()` (its two AppStorage inits) before it strips "person/" and then every "/".

   I moved this logic into `AccountService.loginSucceeded(_:)`, `AccountService.createdCategory(_:name:)` and `PeopleRepository.slug(_:)` without changing it. The call sites, their evaluation order and the wire requests are unchanged.
   The new tests cover a login answer with mixed value types (rules out a `[String: Bool]` cast), invalid JSON throwing, a numeric, missing or string id (a string id gives nil, as in the binary), and slugs with and without the "person/" prefix and a leading slash. The trap paths (missing "success", JSON that is not an object) cannot run under XCTest.
   Two spots are checked by reading only, without unit tests:
   - `Network.fetchMovies` (0x100041370) sends exactly `X-Hdrezka-Ios-App` and `X-Hdrezka-Ios-App-Version` through `AF.request(String, method: .get, encoding: URLEncoding.default, headers:)`.
   - `HeaderUpdater.getHeader` (0x1000b8cc8) passes `headers: nil`.

   A `URLRequest` seam would make `fetchMovies` throw synchronously when the mirror is invalid. `AF.request(String)` instead puts the invalid-URL error into the response, which the original drops. A headers-only accessor would bring back the race from finding 2.
